# 2004/jdalbec

Difficulty: Hard

1. Trigraphs and a two pass preprocessor build

Every `#define` is written as `??= define`. `??=` is a trigraph, an old three
character spelling of `#`. The Makefile first runs the preprocessor with
trigraphs turned off, so the `??=` lines pass through untouched, then runs
`sed` to delete the space in ` (` so names like `In (` become `In(`, and only
then compiles with `-ansi`, which turns trigraphs on. So the macros only come
to life in the second pass, and reading the source you have to apply them in
your head.

2. Macros for keywords and common phrases

`Re` is `return`, `FO` is `for`, `Ir(x)` is `if (x)`, `Sc` is `struct`, `Te`
is `typedef`, `Cs` is `const` and `Si(x)` is `sizeof (x)`. Loops are hidden in
`Fr(cond)` and `Fe(cond)`, which expand to `for (I = 0; cond; I++)` and
`for (In = 0; cond; In++)`. `Ba` and `Be` read characters `B[I]` and `Br[I]`,
`Nb` is the bounds check `N > N && N > -O`, and `II` declares `I I, In`.
`Cl(x)` writes `x` twice, so `Cl(BF = Sb(Br, I); )` is two copies of the
same statement and `Cl(: (At(), B))` gives both branches of a `?:` the same
"abort" fallback.

3. Typedefs with one letter names

`C` is `char`, `I` is `int`, `V` is `void` and `Si` is `size_t`. A line like
`I I;` declares an `int` called `I`, which works because a local variable may
hide a type of the same name.

4. One name used for many things

`B` is a struct tag, a pointer typedef, a struct member, a macro parameter and
a local variable, for example `B B; B = NB(...); B->B[N]`. `Br` is the same
for the list of buffers, and `C` is a type, a variable and `argv` in `main`.
The compiler can tell them apart from their position but a human cannot.

5. Code generated by a token pasting macro

`Tm(B,C)` builds a whole "safe buffer" type: the struct, `NB` (new), `FB`
(free), `BC` (get) and `CB` (set). `##` glues the arguments into the function
names. `Tm(Br,B)` reuses it to make a list of buffers with `NBr`, `FBr`,
`BrB` and `BBr`. The getter returns `0` when the index is out of range, and
the setter ignores out of range writes of `0`, which the program relies on to
end strings and lists without storing a terminator.

6. Library functions behind function pointers

`At` is `abort`, `F` is `free`, `Mo` is `malloc`, `Pr` is `printf` and `P` is
`putchar`, all stored in global function pointer variables with element
names.

7. Constants hidden in strings and global variables

`Zr`, `O` and `W` are the constants 0, 1 and 2. `Xe = "111%%d:\0\n"` hides two
strings: `W * W + Xe` skips 4 characters to reach the format `"%d:"`, and
`Xe[W << W]` is `Xe[8]`, the newline. `O[Na]` is `Na[1]`, the space after `H`
in the periodic table. `W[H]` and `O[U]` (`"22"[2]` and `"3"[1]`) are both
`'\0'`, written with `a[b]` swapped to `b[a]`. The digit offset `'0'` is
calculated as `Si(H)**H - Si(U)**U`, which is `3 * '2' - 2 * '3'` = 48.

8. Comma operators and ternaries in place of if/else

Conditions like `(W, B = Mo(...))` and `(O, C = Be)` start with a constant
followed by a comma that does nothing. Memory checks are nested `?:`
expressions that call `At()` on failure. The splitting step in `Sr` is one big
`?:` with comma lists in both branches instead of an `if`/`else` block.

9. Hidden "settled" look-and-say

`Dy(B, N)` does two jobs depending on `N`. With `N = 0` it returns the next
look-and-say term. With `N = 2` it also frees its input and writes the end
marker at `In - 2`, cutting off the last run, whose count may still change
once the string is joined to whatever follows it.

10. Odd variable types

The run counter `Cr` is a `char`, so counts of 10 or more print as `:` and
other symbols, and 257 or more wrap around. `Co` also returns a `char`
difference.

11. Misleading names and ASCII art

All names are chemical elements, and the periodic table string is only used
for its second character. The block of empty `{ }` braces at the end of
`main` spells "OBFUSCATED C" and does nothing except the useless expression
statement `C;`.
